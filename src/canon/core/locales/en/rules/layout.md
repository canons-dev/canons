# Instruction layout (canons)

- **L1** The block in `AGENTS.md` and the files under `.agents/rules/canons/` are generated by `canons update`. Put project changes outside them, or propose them upstream; `canons verify` rejects hand edits.
- **L2** Rule frontmatter declares `paths` as a YAML block list using `*`, `?` and `**` (`**/` also matches zero directories); parentheses and brackets are literal. Empty or unparsable lists are errors. A rule without `paths` is global, but it must not be used to move red lines out of `AGENTS.md`. An optional `anchors` list names code symbols the rule pins; `canons verify` fails when one no longer appears in the source directories, so the rule is updated together with a rename.
- **L3** Links inside a rule resolve from the rule's own directory (for example `../../doc/x.md`), not from the repository root.
- **L4** No `AGENTS.override.md` in the repository: Codex reads it instead of `AGENTS.md`. Nested `AGENTS.md` files are allowed, but each root-to-directory chain must stay under 32 KiB in total, or Codex silently drops the rest.
- **L5** Client configuration and permissions stay in each client's own directory; an allow-list for one client never authorizes another. A new client gets a thin adapter (a relative symlink or a one-line pointer), never a copy of the content.
- **L6** Skills describe the capabilities they need in plain terms; anything client-specific (parameters, UI, delegation) needs a stated fallback, and required confirmations and verification stay mandatory.
