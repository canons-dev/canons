## Agent 协作约定（canons）

本区块适用于在本仓库工作的所有 coding agent（Codex、Claude Code、Cursor、Copilot 等）。区块外的项目规则在此基础上补充；项目规则可以收紧 C1、C3、C8、C9、C11、C12，但不能放宽。

### 真源与加载

- **C1** 只编辑实体真源：`AGENTS.md`、规则目录（`.agents/rules/`）和技能目录（`.agents/skills/`）。`CLAUDE.md`、`.claude/rules`、`.claude/skills` 等客户端入口都是指向它们的相对软链接。禁止把内容复制成第二份文件，禁止反向链接。
- **C2** 三层加载：本根文件放全局红线；规则目录里带 `paths` frontmatter 的规则放子系统约束；技能放按需加载的多步流程。全局红线不得下放到下层。
- **C3** 修改前运行 `npx canons scopes <文件或目录>...`（新文件传拟创建路径），读完列出的每条规则。完成前对实际 diff 运行 `npx canons scopes --changed`。没有命中不等于没有约束：本文件始终适用。客户端原生加载规则只是便利，不能代替查询。
- **C4** 本文件保持在字节预算内（`npx canons check` 会检查）。需要腾空间时精简措辞或把理由移进文档，绝不删红线。

### 知识与文档

- **C5** 要求 agent 记住的约定必须写进仓库文件、经 git review，不能只存在客户端的私有 memory 里。
- **C6** 文档和规则只写当前知识及其理由，不写历史。能从代码直接看到的事实只留指针、不复述。必须守住的不变量用测试守护。同一约束只写在一处。
- **C7** 临时文件、一次性脚本和在途方案放 `tmp/`（git 忽略）。可复用的工具必须入库。文档和代码不得指向 `tmp/` 里的文件。

### 协作与授权

- **C8** 没有用户明确指令，不改变 Git 状态（commit、push、pull、fetch、merge、rebase、reset、stash、tag、切分支、建 PR）。只读命令不受限。已授权任务所需的步骤不必重复确认。
- **C9** 改动前先 `git status`，不覆盖他人的在途修改；要改另一个 session 正在改的文件，先确认。并行工作优先用独立 worktree；worktree 不隔离数据库、端口等共享资源。
- **C10** 需求、行为、接口或命名有实质歧义，或用户的决定与本约定冲突时，明确指出并等待决定。给出 2–4 个互斥选项，推荐项放第一个并说明代价。
- **C11** 未验证的判断要标注为未验证，并写明依据和验证方法。二手结论注明来源，不得升格为事实。
- **C12** 缺少某种能力（没有子 agent、没有浏览器、没有提问界面）只改变做法，不改变要求：必需的确认和验证不能跳过，没能验证的内容要如实说明。
- **C13** 把工作交给另一个 agent 时，在 `tmp/` 写下目标、范围、改动文件、设计决定、验证结果、剩余工作和待决项，并显式交给对方。长期知识回写到文档。
- **C14** 每个阶段收尾都要给结清判定：本 session 是否做完、能否归档？没做完就用表格列出待办（事项 | 状态或卡点 | 负责方 | 下一步）。PR 未合、待部署、待复测、待用户决定都算未结清。

### 完成改动

- **C15** 改完代码，在同一次改动里同步：能自动测试的逻辑补测试、更新文档、更新受影响不变量所在的规则。汇报同步了什么；没同步的说明原因。
